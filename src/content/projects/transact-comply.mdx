## The problem

Transact Comply watches bank and fintech transactions for signs of money laundering. To do that, it needs rules: flag this pattern, ignore that one.

Every new client needed their own set. Writing those rules by hand, then building test data to prove they worked, took about a month per client. So we could only onboard one client at a time.

## What I did

1. **Listened to clients first.** I sat in demos and onboarding calls across capital markets, banking, NBFC, insurance, housing finance, crypto and payments, and used them to learn what clients actually needed.
2. **Made client data predictable.** I defined one standard format for 20+ types of client files, so every rule reads the same fields the same way.
3. **Built an AI workflow for rules.** In Claude Code, on top of our existing rules engine. Describe a scenario in plain English and it writes the rule, its test data and the setup to deploy it.
4. **Automated file intake.** Client files arrive over SFTP and are checked and processed automatically. Clients get an email when files are received, processed and flagged.
5. **Built a rule search.** Describe a scenario and it shows the rules that already cover it. Sales, implementation and product all use it.

## Four checks before a rule goes live

The AI writes the first draft. Nothing goes live on its word alone.

1. **Format check.** A rule that uses a field that doesn't exist is rejected instantly.
2. **Regression test.** A set of expert-approved rules is re-tested on every change. If results shift, the change is blocked.
3. **Its own tests.** Every rule comes with data that should trigger it, data that shouldn't, and borderline cases. Fail one and it's rejected.
4. **A domain expert.** Still signs off, but in minutes instead of days, because the test results are already attached.

QA gained the most. Test data now comes with every rule, so every rule gets tested, not just a sample.

## Results

Rule setup for a new client dropped from about a month to under 48 hours. We grew from 1 client to 20+, and demos now run on rules built for each client's own scenarios instead of a generic set.

## What I'd do differently

In early demos I led with how many rules we had: 220+. Clients didn't care. They picked three or four scenarios and asked how well we covered them. Asking that sooner would have got us to the rule search much earlier.
